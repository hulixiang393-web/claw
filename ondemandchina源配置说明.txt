【重要结论·先读这个】
本站在数据层（分类 / 详情 / 搜索 / 分集列表）是纯 GraphQL API（Apollo Client），
接口公开可达、无需登录，数据层配置可直接做。但【播放地址层存在阻塞】：
   1. 电影用 `directPlay`、剧集用 `Episode` 查询，返回的 `link` 是【前端路由】
      （如 /watch/ip-man-3/ep-1），【不是可直接播放的视频直链】。
   2. 真实视频地址（cloudfront m3u8/mp4）由浏览器在 /watch 页内加载时，再发起
      带鉴权的请求获取，不走公开 GraphQL 查询。
   3. 本项目框架的 `api_endpoints.episode` 只能返回「一个URL字符串」给播放器，
      且入参是 episode_url、可替换占位符仅 {id}/{bvid}/{cid}/{quality}，
      没有 programSlug/episodeNumber/kind 参数化能力，无法映射 ondemandchina
      的 `Episode(programSlug, episodeNumber, kind, part)` 查询。
   ⇒ 因此当前框架【尚未内置】能拿到 ondemandchina 真实视频直链的取流通道。

   ----------------------------
   这份文档的价值：数据层（列表/搜索/详情/分集）的完整配置已探明可直接落地，
   播放层给出方案选项与待办标记。它不是一份"填完就能播"的成品配置，
   而是一份【按制作标准逐字段说明 + 当前可做配置 + 播放缺口】的完整手册。

 一、站点结构（实测结论）
================================================================================
分类页 /category/movie 返回 3157 字节 HTML，仅含 <script src> 外壳，是 SPA
（React + Apollo）。所有数据走 GraphQL：

   GraphQL 端点：https://graphql.odkmedia.io/graphql   （POST JSON）
   必需请求头：  Content-Type: application/json
                 User-Agent: <浏览器UA>
                 graphql-client-name: web
                 graphql-client-version: 1.0
                 Referer: https://www.ondemandchina.com/

关键 kind 映射（真实 JS 逻辑）：
   series(剧集) → URL段 ep    movie(电影) → URL段 main
   trailer → trailer   clip → clip   extra → additional
看页 URL 规则：/watch/{slug}/{kind段}-{集号}[-part]
   电影     /watch/ip-man-3/ep-1
   剧集第2集 /watch/qingchuans-veil-of-vengeance/ep-2

分类 slug（实测可用）：
   movie  电影    total=143
   drama  剧集    total=369
   （首页分类导航的完整 slug 列表请用编辑器「发现」「分类列表」测试按钮确认）

二、GraphQL 查询定义（实测原始）
--------------------------------------------------------------------------------
1. 列表 ProgramList（发现页/分类页用）
   query ProgramList($categorySlug:String!,$releaseStatus:String,$genreSlug:String,
                     $sortFilter:String,$page:Int){
     programs(categorySlug:$categorySlug,releaseStatus:$releaseStatus,
              genreSlug:$genreSlug,sortFilter:$sortFilter,page:$page){
       totalCount
       nodes{ id slug titleZhHans titleEn titleZhHant
              categories{slug}
              images{poster posterZhHans posterEn posterZhHant}
              meta{isSeries produceCountries episodeTotal ccLanguages}
              produceYear latestEpisode{titleZhHans} releaseStatus }
       pageInfo{hasNextPage nextPage}
   }}
   实测返回：totalCount=143，hasNextPage=true，nextPage=2
   节点例：{id:24305, slug:"ip-man-3", titleZhHans:"叶问3",
            images.posterZhHans:"https://d2y2efdi5wgkcl.cloudfront.net/fit-in/880x1280/media-io/2025/2/25/ip-man-3.f205f8ac.jpg",
            meta.isSeries:false, produceYear:2016}

2. 详情 ProgramDetail
   query Program($programSlug:String!){
     program(programSlug:$programSlug){
       slug titleZhHans titleZhHant synopsisZhHans
       meta{isSeries episodeTotal episodeOrdering score produceCountries}
       images{poster posterZhHans thumbnail}
       categories{slug titleZhHans} genres{slug titleZhHans}
       produceYear releaseStatus releaseStart } }
   实测：叶问3 synopsisZhHans=<剧情简介>，categories:[{slug:movie}],
         genres:[{slug:action-adventure,titleZhHans:"动作与冒险"}],produceYear:2016

3. 分集列表 EpisodeList（剧集用；返回每集的 link 路由）
   query EpisodeList($programSlug:String!,$ordering:EpisodesOrderTypes!,$page:Int){
     episodes(programSlug:$programSlug,ordering:$ordering,page:$page){
       totalCount pageInfo{hasNextPage nextPage}
       nodes{ id link titleZhHans titleEn synopsisZhHans
              images{thumbnail} videoDuration videoCcLanguages } } }
   ※ ordering 枚举值需在编辑器「测试」中确认（number_asc 等候选已试，待定）

4. 播放详情 Episode（剧集单集；kind 取 "series"）
   query Episode($programSlug:String!,$episodeNumber:Int!,$kind:String!,$part:Int){
     episode(programSlug:$programSlug,episodeNumber:$episodeNumber,
             kind:$kind,part:$part){ link titleZhHans videoDuration
               nextEpisode{link titleZhHans} } }

5. 电影直播 DirectPlay（电影；返回单条 link 路由）
   query DirectPlay($programSlug:String!){ directPlay(programSlug:$programSlug){link} }
   实测：link=/watch/ip-man-3/ep-1

6. 搜索 Search
   query Search($keyword:String,$category:String,$genre:String,$person:String,
                $produceCountry:String,$produceYear:String,$page:Int){
     search(keyword:$keyword,category:$category,genre:$genre,person:$person,
            produceCountry:$produceCountry,produceYear:$produceYear,page:$page){
       totalCount pageInfo{hasNextPage nextPage}
       nodes{ slug titleZhHans id images{posterZhHans}
              meta{isSeries episodeTotal}
              categories{slug titleZhHans} genres{slug titleZhHans}
              produceYear releaseStatus } } }
   实测：搜"叶问"，totalCount=17，首条 ip-man-3 覆区如上。

 四、播放链路分析（关键决策点）
================================================================================
【电影】程序：detail 拿到 slug → directPlay 查电影播放入口。
   directPlay 只给 link=/watch/ip-man-3/ep-1（前端路由），非视频地址。

【剧集】程序：detail.meta.isSeries=true → EpisodeList 拿 {episodeNumber,link} 分集
   → 逐集 Episode(programSlug,episodeNumber,kind="series") 取该集 link（仍为路由）。

【两个可行的取直链方案（需要框架/video_view 侧支持，非纯配置）】
  A. 在 Episode/directPlay 查询追加视频流字段：去 JS bundle 找 watch 页实际调用的
     视频查询（可能带鉴权 token），把真实 m3u8 URL 从该响应里取。需浏览器渲染。
  B. 用 render("playwright") 渲染 /watch/xxx 页，等 video.src 出现后从页面提取
     cloudfront m3u8 直链。可行但慢（改版风险高）。

  当前框架 endpoints/episode 的 HTML 解析支持的 play_url.selector/page render 仅对
  传统后端渲染站有效，对 SPA 无预渲染内容的 watch 页拿不到视频。◆ 建议先在
  framework/content.py + source-schema 增加「programSlug/episodeNumber/kind」参数
  支持，再实现 A 方案查询视频流字段。

 五、GUI 分步制作（按源编辑器 ui-editor.md 界面操作）
================================================================================
前置：源码运行需能访问 graphql.odkmedia.io；推荐先不加反爬（站点透明）。

第1步：进入源编辑器
  主窗口 → 【源管理】Tab → 底部「添加源」按钮
  → 弹出源编辑器对话框（新建模式，复制 template.example.json 模板）

第2步：设基本信息（编辑器顶部表单）
  · 源名：OdemandChina 中字视频
  · 类型（$type）：选「视频 video」
  · 状态：保持「草稿」（$enabled=false，因为播放未闭环，避免启用后列表可用却播不了）
  · $id：ondemandchina

第3步：填「网络」（transports）
  · 基础URL（base_url）：https://www.ondemandchina.com
  · 请求头：Content-Type=application/json
         User-Agent=<浏览器UA>
         Referer=https://www.ondemandchina.com/
         graphql-client-name=web
         graphql-client-version=1.0
  · 超时 15、重试 3、间隔 500ms

第4步：填「发现」（api_endpoints.discovery）
  · 请求方式：POST
  · URL：https://graphql.odkmedia.io/graphql
  · Body格式：JSON
  · 响应类型：JSON
  · 响应定位（response_path）：data.programs.nodes
  · 请求参数（params）：
      query  = 上面 ProgramList 查询串
      variables = {"categorySlug":"movie","page":1}   （分类先填 movie）
  · 列表项字段映射（item_fields）：
      标题 title  → titleZhHans
      封面 cover  → images.posterZhHans
      年份 update → produceYear
      集数 episode_count → meta.episodeTotal
  · 分类列表（list_item.categories）：先加「电影」「剧集」两个，其余分类 slug 用
    「测试细分页」/预览确认后补全
  · 点「测试发现」：应看到 叶问1/2/3 等约143条  → 验证列表成功

第5步：填「搜索」（api_endpoints.search）   —— 基本同上，仅差异：
  · 请求参数 variables = {"keyword":"{keyword}","page":1}
  · 响应定位 response_path = data.search.nodes
  · 字段映射同上
  · 点「测试搜索」输入"叶问" → 应返回 叶问1/2/3/问心 等17条

第6步：填「详情」（api_endpoints.detail）
  · 请求方式 POST，URL 同上
  · 请求参数：
      query  = 上面 Program 详情查询串
      variables = {"programSlug":"{slug}"}   ← {slug} 从 item.url 模板里提取
  · 响应定位 response_path = data.program
  · 字段提取（field_extractors）：title/summary/cover/genres 见第三节
  · 分集（chapters）：电影 = directPlay，剧集 = EpisodeList，见第四节（当前无法用
    模板直拼 url_template，需二次实现，先留空）

第7步：填「正文/播放」（api_endpoints.episode 或 endpoints.content.episode）
  ⛔ 全片最关键：当前框架【无法】把 Episode 查询映射成播放地址。
  · 先记下：antv ondemandchina 的播放返回是前端路由 link，不是直链。
  · 若按当前框架硬填，最多能到分集列表，点播放会失败（VLC 拿路由 URL）。
  · 真实可播需先在框架加参数支持（见第四节方案A/B）后，才能在此填 query。

第8步：填「媒体」（media）
  · 格式 format：hls
  · 合并 merge：ffmpeg / mp4

第9步：保存与校验
  · 点「保存」：SourceConfig 严格校验。因播放字段留空，可能报必填缺失。
  · 允许以「草稿」保存（$enabled=false）——源管理里可见但不启用。
  · 校验失败会标红错误字段，按提示修正数据层字段；播放缺口会一直提示，
    属预期（详见文末【待实现】）。

第10步（后续）：待框架支持后补播放，再从源管理点亮启用。
