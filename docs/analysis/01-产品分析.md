# claw「多源爬虫框架」产品分析报告

> 只读分析（产品经理视角）。已通读 docs/ 全部设计文档、gui/app.py 与 8 个 Tab 页面、reader 四视图、framework 全部内核模块、11 个源配置样例、git 历史。以下结论均以代码为准。

---

## 1. 产品定位

**一句话**：一个"改 JSON 就能加站点"的多源聚合桌面应用 —— 把十几二十个小说/漫画/视频站统一进一个 GUI，逛站、搜书、阅读、播放、下载、收藏闭环，站点规则全部外置在 `sources/*.json`。

- **解决的问题**：分散在各站点的内容需要 N 个书签、N 种播放器、手动搬运下载。此产品把它们收拢成一个"私人内容中心"，并让"加新站点"不依赖改代码。
- **目标用户**：懂一点技术的 ACG/二次元内容消费者（追小说、漫画、番剧），以及愿意自己折腾源配置的进阶用户。从内置 30+ 源（含 YouTube/B站/番茄/纵横 + 一批成人站）看，实际画像偏"追更党 + 收藏党"，自用型工具而非大众产品。
- **核心价值主张**：
  1. **配置驱动**（`framework/config.py` + `sources/*.json`），框架零站点硬编码；
  2. **真·多引擎**：HTML selector、JSON API、B站 wbi 签名、AES 图片解密、番茄字体混淆 translit、MacCMS 多播放源换源、Playwright 渲染 canvas 分片、yt-dlp 引擎——不是玩具级爬虫，是能啃硬骨头的工程；
  3. **自包含闭环 + 自愈体系**：健康灯/自动禁用/源编辑器实时预览，让"源坏了怎么办"在 GUI 内可处理。

---

## 2. 核心功能闭环：发现 → 阅读/播放 → 下载 → 收藏

| 环节 | 体验 | 关键实现 |
|---|---|---|
| 发现/逛站 | ★★★★★ 最强 | `gui/pages/discover_page.py`：按类型分组源选择器+健康灯、分类折叠栏、懒加载网格（首屏 1+2 页并发预加载、epoch 防竞态、URL 跨页去重）、详情抽屉、AES/Playwright 封面异步恢复、全量索引 |
| 搜索 | ★★★★★ 强 | `search_page.py`：跨源并发、每源状态 chip、边抓边显示（第 1 页秒出）、来源角标点击筛选、合并相似开关、批量勾选加入书架/下载 |
| 阅读/播放 | ★★★★☆ 强但偏科 | 小说（滚动/翻页双模式、章节预加载、A+ A- 字号、卷章复合自动排序）；漫画（画廊/横向、Ctrl+滚轮缩放、自动下一话）；视频（内嵌 VLC、本地 HTTP 代理解决 TLS 兼容、看门狗自动降级、多源换源、画质选择、全屏、播完续播） |
| 下载 | ★★★★☆ 强 | `download_queue.py`+`downloader.py`：并发槽、暂停/继续/取消、单章重试 3 次、ffmpeg dash 双流合并、漫画 Playwright 批量渲染复用 Chromium、最终统一合成 epub |
| 收藏/书架 | ★★★☆☆ **最薄弱** | `library_store.py`（收藏元数据+收藏夹）+ `library_page.py`（本地 epub + 收藏聚合） |

**结论**：发现/搜索/阅读/下载四个环节完成度极高。**最薄弱的两处是"收藏/书架"的断点，以及"全量抓取索引"没有消费入口**。

## 3. 用户体验问题

### 3.1 续读记忆 24 小时硬过期，收藏了也照样丢 ★★★★★
- **现象**：`framework/reading_progress.py` 定义 `MEMORY_TTL_SECONDS = 24*3600`；`app.py` 启动时 `prune(shelf_cb=None)`，`prune` 传 `None` 时**所有**过期条目一律删除（书架回调分支被跳过），即**已收藏的书也丢续读位置**。书架卡片的"读到第45章"角标过期即消失。
- **影响**：追更用户 2 天后再打开，回到第 1 章。
- **建议**：P0。改为"收藏则永久保留续读、未收藏 24h 清理"，把 `prune` 真正接入 `LibraryStore.has()` 回调；或把 TTL 提为设置项。

### 3.2 视频本地下载产物进不了书架 ★★★★☆
- **现象**：`library_page._refresh_data` 只 `sub.glob("*.epub")`；而视频下载产出的是 `{output_dir}/{书名}/*.mp4`。书架扫描不到任何 mp4。
- **影响**：书架是"本地已下载内容 + 收藏聚合"，但**视频下载区完全缺席**。
- **建议**：P0。按 `book_dir` 扫描扩展名（epub/mp4/txt），视频显示"共 N 集"，点击打开所在文件夹。

### 3.3 全量抓取索引无消费入口 ★★★★☆
- **现象**：`bulk_fetch.py` 抓完把 `data/works_index_{source_id}.json` 落盘，唯一消费者是首页"检查更新"。书架、发现页都没有浏览/搜索本站索引入口。
- **影响**：这份价值**只有数据没有界面**。
- **建议**：P1。在发现页或书架加"索引浏览"视图。

### 3.4 网络设置改了不生效（"应用"是假生效）★★★★☆
- **现象**：`settings_page._on_apply` 写进 `app_config.json`，但 `HttpClient` 的 `NetworkDefaults` 是**构造时快照**。每个源多数没配显式值 → 走全局 → 还是旧快照。
- **影响**：用户改 UA/代理/超时后点"应用"，当前会话内不生效（需重启），与文档"实时生效"不符。
- **建议**：P1。要么 `settings_manager` 变更时热更新 `HttpClient`（`update_defaults()`），要么如实标注"重启后生效"。

### 3.5 启动即对全部启用源并发自检 ★★★☆☆
- **现象**：`app.py` 对每个启用源起一个自检任务。30+ 源就是 30+ 并发首屏请求。
- **影响**：对源站礼貌性差、容易被风控，无间隔/限流/队列。
- **建议**：P1。改为串行或 2~3 并发、间隔 300~500ms。

### 3.6 失败恢复路径弱 ★★★☆☆
- **现象**：失败只写在 `status_label`（一行灰字）；搜索单源失败藏在 chip ToolTip 里。
- **影响**：源坏了用户不知道去哪修，和"源管理→诊断"的闭环断裂。
- **建议**：P1。给失败 chip/状态条加"点击展开错误 + 一键跳诊断"。

### 3.7 合并相似结果"各源版本展开"是半成品 ★★★☆☆
- **现象**：`merge_similar` 生成 `variants` 并改标题，但卡片**只显示代表卡**，无展开 variants 交互。
- **建议**：P2。卡片加"N 个源 ▾"展开。

### 3.8 细节瑕疵（小）★★☆☆☆
- `app.py` `_build_settings` 的 `return` 后有不可达语句。
- `download_page.py` 顶部 `ENABLE_TRAY = True` 旧遗留常量。
- `home_page.py` docstring"暂占位"但代码已完整实现。
- 空状态/吉祥物是 QPainter 占位，theme.md 的"Q 版插画"承诺未兑现。
- 搜索历史只有展示，无清空/管理入口。

## 5. 差异化与竞品

| 维度 | 本框架 | Tachiyomi / Legado / 阅读类 | yt-dlp GUI 类 |
|---|---|---|---|
| 内容类型 | **三类型统一**（novel+comic+video 一个 GUI） | 通常单一类型 | 仅视频 |
| 站点接入 | JSON 配置 + **GUI 内源编辑器实时预览** | 扩展插件 | 现成站点 |
| 对抗能力 | AES 图解密、番茄混淆、B站 wbi、MacCMS 换源、Playwright canvas、代理池 auto、m3u8 广告剔除 | 弱到中等 | 靠 yt-dlp 内核 |
| 自愈 | 健康灯+自动禁用+诊断+跳编辑 | 多数无 | 无 |
| 分发 | 源码 + PyInstaller，依赖 VLC/ffmpeg/playwright/yt-dlp，偏重 | 轻 | 中 |

**真正的差异化优势**：
1. **"源制作 IDE"内置**：`source_editor.py` 表单 + `preview.py` 实时选择器命中/测试搜索/测试详情 + 诊断一键跳失败字段。
2. **对抗性爬取的工程深度**：加密图片流式解密、Playwright 视口复用 canvas、VLC 本地代理绕过 TLS、MacCMS player_aaaa 换源解析。
3. **内容格式标准**：下载统一产出 epub，对接阅读生态。

**短板**：
1. **无扩展仓库/源分享生态**。
2. **多端与云同步缺席**（WebDAV 仅存值）。
3. **依赖链重**（VLC + ffmpeg + playwright + yt-dlp）。
4. **测试缺失**。
5. **合规包袱**。

## 7. 风险

### 7.1 技术风险
- **依赖链复杂**：VLC（未装则播放只剩"复制地址外开"）、ffmpeg、playwright、yt-dlp。任一缺失都是半残功能，跨平台未验证。
- **无测试的并发代码**：download_queue 暂停/取消竞态、discover 多页并发 epoch、Playwright canvas 滚动提取。
- **站点规则易碎**：Playwright 分片提取、续页探测、反爬特征词表随站点改版失效。

### 7.2 内容合规风险（最高）
- **内置成人源默认启用**：`sources/` 含 18mh、pornhub、missav、hanime1、avgood、wnacg 等且 `$enabled: true`。`downloads/` 已出现成人内容文件。
- **版权风险**：正版站点抓取与批量下载无免责/授权提示。
- **建议**：至少加"首次启动内容风险提示 + 成人源默认禁用 + 设置里可隐藏成人类"，并默认分离成人源与正规源。

### 7.3 维护风险
- **单点维护**：个人项目，30+ 份源 JSON 随站点改版持续维护，长尾工作量远大于框架本身。
- **文档与代码漂移**：架构仍规划 Scheduler/CLI/测试体系但未实现；home_page docstring 与实现不符。
- **schema 演进**：decryption 已出现 schema 未登记的策略（translit、map_module），"配置驱动"边界在实操中被突破。

---

**一句话总结**：工程完成度远超同类个人工具、核心爬取/阅读/下载能力很强、自带源制作 IDE 的高质量自用型框架；它最大的产品问题在"闭环的末端"（续读记忆过期、视频下载不进书架、全量索引无入口），最大的工程问题是**自动化测试近乎为零**，最大的商业风险是**默认内置成人源**。
