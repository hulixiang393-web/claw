# 手动播放源可用性检测设计

## 目标

在阅读界面提供手动「检测播放源」入口。用户主动触发后，异步检测当前视频详情中的播放源，最多检测 5 个不同线路；只有成功解析到可播放地址的线路才在播放源下拉框中标记，失败或未找到地址不标记。

## 交互

- 阅读界面播放源下拉框旁增加「检测播放源」按钮。
- 不自动检测，不在进入阅读界面、加载详情或切换集数时触发网络探测。
- 检测期间按钮禁用并显示检测状态；用户仍可播放已经选定的线路。
- 检测结束后恢复按钮，成功线路显示「可播放」标记；失败线路保持原名称，不显示错误标记。
- 切换作品或换源时取消旧检测结果，避免旧线路标记污染新作品。

## 通用配置

在通用媒体配置中增加：

```json
{
  "media": {
    "source_probe": {
      "enabled": true,
      "max_sources": 5,
      "concurrency": 1,
      "timeout_ms": 30000
    }
  }
}
```

`enabled=false` 时隐藏或禁用检测按钮；`max_sources` 强制限制在 1～5；`concurrency` 默认 1，避免同时请求过多触发反爬。源未配置 `source_switch` 或只有单线路时不执行多线路探测。

## 检测流程

1. 用户点击按钮。
2. 读取当前详情的播放源列表，按源 ID 去重并截取前 `max_sources` 个。
3. 后台任务逐个调用现有取流解析器，使用独立检测上下文和 `timeout_ms`。
4. 解析到非空且格式有效的媒体 URL 后记录该源成功；普通解析失败、验证页或无播放地址均记录失败但不标记；单个线路超过 30 秒标记「超时」后立即进入下一个线路。
5. 回到主线程更新下拉框显示；使用作品/换源代次校验，丢弃迟到结果。
6. 不缓存失败结果；成功结果可复用现有短期流缓存，但不改变当前播放源。

## 安全与性能

- 不绕过 WAF、验证码、登录或防盗链。
- 默认串行检测，一次最多 5 个线路。
- 不记录完整播放 URL、签名参数或 Cookie。
- 检测失败不影响当前播放和详情显示。

## 测试

- 配置开关关闭时按钮不可用且不发请求。
- 手动点击才启动检测，进入阅读界面不自动启动。
- 最多检测 5 条、按配置串行执行、线路去重。
- 成功线路标记，失败/空地址不标记。
- 换作品或换源后旧结果丢弃。
- 检测期间不阻塞界面，按钮状态正确恢复。
