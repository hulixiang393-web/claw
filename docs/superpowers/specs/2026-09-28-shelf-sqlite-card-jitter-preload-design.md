# 书架 SQLite 缓存、卡片稳定渲染与章节预加载设计

## 目标

解决搜索页、发现页、书架页在卡片数量较多或封面异步加载时的抖动和卡顿，并建立可扩展的书架离线缓存：书架卡片优先从本地数据库和缓存显示，小说/漫画阅读时以当前章节为锚点向后预加载可配置数量的章节。

阅读位置、章节目录、书架元数据永久保留；正文和漫画图片属于可清理内容缓存。默认自动清理周期为 30 天：会话长期没有变化时清除内容缓存，但保留该书最后阅读章节和精准位置。

## 当前项目约束

- 项目没有 SQLite/关系型数据库；当前已有 `RedisLikeStore` 压缩文件缓存、`reading_progress.json` 和多处内存缓存。
- SQLite 使用 Python 标准库 `sqlite3`，不新增第三方数据库依赖。
- 不把大正文或漫画图片作为 SQLite BLOB；数据库只保存索引、元数据和状态，正文/图片保存为文件。
- 搜索、发现和书架卡片必须保持固定尺寸，异步内容完成不能引起卡片高度变化或全网格重建。
- 迁移公共缓存接口时必须盘点并修改全部调用方，不能只替换底层实现。

## 设计范围

包含：

- SQLite 书架数据库和文件内容缓存仓库。
- 书架元数据、章节目录、阅读位置、缓存窗口和清理状态。
- 小说正文与漫画图片的持久化、窗口滚动淘汰和异步预加载。
- 搜索页、发现页、书架页的批量卡片创建、布局更新和封面加载。
- 设置页的预加载数量、容量、自动清理和清理按钮。
- 旧 `reading_progress.json`、现有书架缓存和缓存 API 的迁移与兼容。

不包含：

- 视频内容缓存和视频播放进度。
- 修改每个视频源配置。
- 把所有历史作品内容一次性下载到本地。
- 破坏现有书架、阅读器、源解析和章节排序 API。

## 一、缓存分层架构

### 1. SQLite 元数据层

新增书架缓存数据库，例如 `data/cache/shelf.db`。数据库只保存可查询的轻量状态：

- `books`：书架作品 key、source_id、book_url、content_type、标题、作者、封面路径/哈希、更新时间、最后阅读时间、最后阅读章节。
- `chapters`：book_id、章节序号、章节 URL、标题、章节内容类型、永久目录字段。
- `reading_locations`：book_id、chapter_url、小说文本锚点或漫画图片锚点、滚动/页索引回退值、updated_at。
- `cache_entries`：book_id、chapter_url、内容类型、文件路径、字节数、内容哈希、创建时间、最后访问时间、缓存状态。
- `sessions`：book_id、当前章节、预加载窗口起止位置、最近成功预加载时间和会话更新时间。
- `settings`：缓存策略版本和必要的迁移标记；应用设置主来源仍为 `SettingsManager`。

所有变更通过 `ShelfCacheRepository` 完成，写入使用事务。数据库只引用文件，不存大型正文或图片 BLOB。

### 2. 文件内容层

建议目录：

```text
 data/cache/shelf-content/<book-key>/
   novel/<chapter-key>.txt.zst-or-gzip
   comic/<chapter-key>/<image-index>-<image-key>.img
   manifest.json
```

实际压缩算法复用项目已有可用标准库/依赖；若当前没有 zstd 依赖，使用 gzip，不为缓存专门引入大型依赖。文件写入先写临时文件，再原子替换；数据库在文件提交成功后更新为 `complete`。

URL 只作为章节/图片更新和重新获取的依据，不能作为离线显示的唯一数据。漫画图片必须保存实际字节，以免签名 URL 过期导致书架离线打不开。

### 3. 生命周期

- 加入书架：保存书籍元数据、封面和完整章节目录；不立即下载所有正文/图片。
- 打开书架卡片：先读 SQLite 元数据和本地内容缓存；已有内容直接显示，缺失内容才由后台任务加载。
- 阅读推进：以当前章节为锚点维护 `current + N` 的活动窗口；成功写入新内容后删除窗口外内容文件和索引。
- 移出书架：删除该书的元数据、目录、阅读位置、会话记录和内容缓存文件。
- 清除缓存：只删除正文/图片文件及 `cache_entries`，保留书架元数据、章节目录、阅读位置和会话状态；再次进入该书时才回源。
- 自动清理：当 `sessions.updated_at` 或最后阅读时间超过 30 天且没有新的阅读变化，只清除该书内容窗口，保留最后位置和目录。

## 二、卡片抖动与卡顿治理

### 1. 统一批量渲染

搜索页、发现页、书架页使用统一的批量渲染节奏：

1. 后台线程准备轻量卡片数据。
2. 主线程按固定批次创建卡片。
3. 批次内暂时冻结目标布局更新，批次完成后只触发一次布局/列宽更新。
4. 通过 `QTimer`/事件循环让出主线程，下一批再继续。
5. 每个页面维护渲染代次，旧搜索、换源、筛选和刷新任务的回调不得写入新网格。

卡片固定宽高和占位区域，卡片创建后不因封面、作者、状态异步变化而改变几何尺寸。追加卡片时：非底部用户位置保持原滚动值，用户贴底时只将视口钉到新底部。

### 2. 封面加载

- 先使用 SQLite/RedisLikeStore/内存缓存中的封面；无缓存时显示固定尺寸占位。
- 网络获取、图片字节解码、缩放和裁剪放到后台任务；主线程只接收最终 `QPixmap/QImage` 并替换固定区域。
- 默认关闭逐卡淡入动画，或合并为批次级更新，避免大量动画同时触发重绘。
- 封面完成只更新目标卡片，不扫描并重建整页网格。
- CoverLoader 继续全局限流、去重和取消过期卡片回调。

### 3. 页面行为

- 搜索页和发现页只创建首屏及有限缓冲卡片，滚动到阈值后追加一批。
- 书架页优先一次性读本地元数据；大量书籍采用固定批次建卡，不能逐条触发布局重排。
- 卡片过多时保留数据，不强制同时创建所有 QWidget；屏幕外内容延迟建卡或采用现有懒加载路径。
- 重新筛选/排序尽量复用卡片数据，只有确实变化的卡片才重建。

## 三、阅读内容缓存与预加载

### 1. 设置

设置页新增：

- `shelf_cache.prefetch_chapters`：当前章节之后预加载的章节数，默认 `10`，允许用户调整。
- `shelf_cache.max_book_cache_mb`：单本内容缓存上限。
- `shelf_cache.max_total_cache_mb`：所有书架内容缓存总上限。
- `shelf_cache.auto_cleanup_enabled`：自动清理开关，默认开启。
- `shelf_cache.inactive_days`：不活跃清理天数，默认 `30`。

设置保存到现有 `SettingsManager`/`app_config.json`，读取时做范围校验和默认值合并。设置变化只影响后续窗口计算，不删除书架位置。

### 2. 打开书架书籍

打开流程：

1. 从 SQLite 读取书籍、目录、最后阅读位置和当前活动窗口。
2. 立即构建 ReaderPage 并显示本地章节/图片内容。
3. 若当前章节缓存缺失，后台加载当前章节；显示“缓存加载中”而不是阻塞页面。
4. 当前章节可用后，以当前章节向后补齐 N 章；预加载任务与当前显示任务分离，当前章节优先。
5. 任务按 book_id/session_id 去重，切书、移出书架或关闭页面时取消旧任务。

### 3. 阅读推进窗口

以当前章节 `current_idx` 为锚点：

```text
保留范围 = [current_idx, current_idx + prefetch_chapters]
```

进入下一章后更新 session 窗口，后台补齐尾部。成功缓存后：

- 写入正文压缩文件或漫画图片文件。
- 事务更新 `cache_entries` 和 `sessions`。
- 删除窗口外内容文件和索引。
- 若单本/总缓存超过限制，优先删除最久未访问且不在当前活动窗口的内容。

当前章节、阅读位置和目录不是内容窗口淘汰对象。

### 4. 失败和恢复

- 单章失败不影响当前章显示，记录失败时间和错误类别，避免立即无限重试。
- 文件存在但数据库缺失时通过 manifest 扫描修复索引；数据库标记 complete 但文件不存在时删除该条目并按需重新加载。
- 应用崩溃或断电时，临时文件清理；启动时校验未完成条目，不把半文件当作可用正文/图片。
- 清理任务不在主线程执行，完成后只发送轻量状态更新。

## 四、缓存接口迁移

先定义统一接口：

```python
class ShelfCacheRepository:
    def upsert_book(...): ...
    def replace_chapters(...): ...
    def get_book_snapshot(book_key): ...
    def get_content(book_key, chapter_key): ...
    def put_content(...): ...
    def update_location(...): ...
    def update_session(...): ...
    def evict_book_content(...): ...
    def clear_content_cache(...): ...
    def cleanup_inactive(...): ...
```

迁移顺序：

1. 建立 SQLite schema、事务、文件仓库和迁移工具。
2. 让 `Content` 的章节正文/漫画图片缓存通过 repository，保留现有 `fetch_chapter`/`fetch_comic_pages` 公共方法签名。
3. 让 `ShelfService` 写入/删除书架时同步维护 repository。
4. 让 `ReaderPage` 在打开、切章、滚动和 flush 时更新 location/session。
5. 让 NovelView/ComicView 的预加载调用统一 repository 任务调度。
6. 让 LibraryPage、SearchPage、DiscoverPage 读取缓存元数据和封面，接入批量卡片渲染。
7. 全局搜索旧 `RedisLikeStore`、`reading_progress.json` 和 `precache_chapters` 调用点，逐个确认迁移或保留兼容适配。

不直接修改公共方法签名，除非先同步修改全部调用方并增加兼容默认参数。

## 五、迁移与兼容

- 首次启动创建数据库并记录 schema version。
- 将 `reading_progress.json` 导入 `reading_locations`，导入后原文件保留备份，重复启动不重复覆盖较新的 SQLite 记录。
- 将现有书架元数据和可识别缓存迁移为数据库条目；无法可靠识别的旧缓存不强行转换，保留旧文件并按需重建。
- 迁移失败时继续使用旧读写路径，不能阻塞应用启动；显示可观察日志。
- 新旧路径并行验证通过后，再考虑删除旧缓存适配层。

## 六、测试与验收

### 卡片

- 搜索、发现、书架各加载大量卡片时，卡片高度稳定，滚动位置不跳，布局更新次数按批次而不是按卡片增长。
- 封面异步完成只更新目标卡片；旧页面回调不会污染新结果。
- 离线书架元数据显示不触发网络请求；缓存封面直接显示。

### 缓存

- 添加书架保存元数据/目录；重启后卡片和目录可离线显示。
- 小说正文和漫画图片命中本地文件时不回源。
- 当前章节推进后只保留当前章+N章，旧内容被删除，阅读位置仍存在。
- 清除缓存后目录/阅读位置/会话状态仍存在，重新进入书籍才产生网络请求。
- 30 天不活跃自动清除内容，位置和目录不变。
- 单本/总容量限制和 LRU 清理不删除活动窗口。
- 中断写入、数据库损坏、文件缺失、重复预加载和切书取消均可恢复。

### 质量门禁

- 新增缓存仓库、迁移、卡片批量渲染、设置、小说预加载、漫画预加载专项测试。
- 运行 `compileall`、项目实际 lint/typecheck（若无配置则记录）和稳定全量 pytest。
- 运行调用点审计，确认旧缓存和 `reading_progress` 调用方没有遗漏。
- 记录性能基线：首屏卡片渲染耗时、布局更新次数、书架离线打开耗时、缓存命中率和预加载回源次数。
