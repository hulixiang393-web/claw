# 视频分片画面广告检测设计

## 目标

针对 HLS 播放流中已经烧录到视频画面的广告，增加可选的轻量画面检测。每个 TS 分片最多抽取开头和中间两帧，使用免费开源的 FFmpeg 与 OpenCV 做低分辨率特征分析；不阻塞首播，只有高置信度确认后才删除广告分片。

## 技术方案

- FFmpeg/ffprobe：读取 TS 分片、定位可解码帧、获取视频流参数。
- OpenCV：将抽取帧缩放到 320×180，计算感知哈希、亮度/饱和度直方图、边缘比例、底部区域差异和重复帧比例。
- 不默认依赖 OCR；广告文字识别只作为后续可选增强，不影响基础安装。
- 所有依赖均为免费开源库，不接入付费 API 或云端识别服务。

## 检测流程

1. MediaProxy 获取 HLS 清单并确定候选 TS 分片。
2. 对每个候选分片异步读取两帧：分片开始附近一帧、分片中点一帧。
3. 先执行廉价特征筛选：编码参数、帧率、分辨率、码率、时长、黑帧/纯色比例、感知哈希和画面重复度。
4. 只有分片与相邻正片在多个特征上同时异常时，才进入广告候选状态。
5. 广告候选需要满足至少两个独立证据：已配置广告关键词的画面区域特征、与广告模板的感知哈希相似、广告连续分片形成稳定区块、或清单协议广告标记。
6. 未达到置信度时保留分片，不能因为单一特征异常删除。

## 播放策略

- 首次播放不等待全量检测，先正常播放。
- 检测任务在 MediaProxy 后台运行，结果写入短 TTL 的内存缓存。
- 已确认的广告分片在下一次清单重写或播放器重试时删除。
- 当前正在播放的清单不动态改写，避免时间轴跳变和 VLC 断流。
- 单个分片检测超时或解码失败时保留，不影响播放。
- 每个 HLS 流限制检测并发数，默认 1～2 个，防止触发 CDN 限速。

## 配置

```json
{
  "media": {
    "frame_ad_detection": {
      "enabled": false,
      "sample_frames": 2,
      "width": 320,
      "height": 180,
      "confidence_threshold": 0.9,
      "max_concurrency": 1,
      "cache_ttl_seconds": 900
    }
  }
}
```

默认关闭，避免首次播放增加 CPU/网络负担；仅对用户开启后启用。源级规则可以提供广告模板哈希或底部区域配置，但不能关闭通用 HLS 协议过滤。

## 安全保护

- 不删除仅因低码率、低帧率、黑帧、重复画面或 `DISCONTINUITY` 出现的分片。
- 保留正常 HLS 的 KEY、MAP、BYTERANGE、音视频同步和必要的协议标签。
- 检测结果只保存脱敏的分片哈希和状态，不保存完整签名 URL、Cookie 或敏感参数。
- 无法确认广告时默认保留，优先保证播放连续性。

## 测试

- OpenCV/FFmpeg 依赖缺失时安全降级，不影响普通播放。
- 两帧抽取、缩放和特征计算测试。
- 正常分片、广告模板分片、纯色分片、重复关键帧和解码失败分片测试。
- 单一异常特征不能删除；多个高置信度证据才标记广告。
- MediaProxy 首次播放不等待检测，下一次清单重写才使用缓存结果。
- 检测并发、TTL、取消、换流和失败保留测试。
- 运行广告过滤、MediaProxy、视频播放回归、compileall 和 git diff check。
