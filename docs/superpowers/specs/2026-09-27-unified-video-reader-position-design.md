# 通用视频播放与精准阅读位置记忆设计

## 目标

解决所有视频源播放过程中的卡顿问题，优先检查和优化公共播放代码、代理、缓存和异步任务调度，不为每个视频源增加单独的加速配置或主动探测。

同时让小说和漫画的书架续读位置稳定到内容位置：小说恢复到同一章节中的同一段文字附近，漫画恢复到同一话中的同一张图片及图片内相对位置。窗口尺寸、字号、图片懒加载进度和应用重启不应导致恢复到明显错误的位置。

## 范围

包含：

- `framework/media_proxy.py` 的统一媒体转发、HLS/DASH/MP4/Range 请求、缓存和并发调度。
- `framework/media_cache.py` 及相关缓存服务的命中、提交、去重和淘汰行为。
- `framework/external_player.py` 的公共播放参数和播放会话生命周期。
- `framework/reading_progress.py` 的通用进度数据结构和持久化。
- `gui/pages/reader/novel_view.py`、`comic_view.py` 的位置采样、锚点生成和恢复。
- 对应的离线单元测试、Qt 阅读器回归测试和代理测试。

不包含：

- 不逐个修改 `sources/*.json` 来配置视频加速。
- 不主动批量读取每个源的 m3u8、分片或测速地址。
- 不默认开启无界多线程预取、不轮换代理出口、不增加激进重试。
- 不改变视频源解析、章节排序、VLC 全集播放列表和源选择契约。
- 不记录视频播放进度；视频位置按现有需求忽略。

## 设计原则

1. 先测量再优化：所有优化必须由公共链路中的请求耗时、吞吐、缓存命中、并发等待或渲染开销证据支持。
2. 源配置只生产媒体地址：源级配置保持兼容，通用播放层依据媒体协议和运行时指标工作。
3. 一次请求一次职责：manifest、分片、key、Range 请求不能因为诊断而重复请求上游。
4. 并发有界且可取消：只有公共代码确认存在可合并的等待时才并发，任务必须去重、限额、超时并能在换书/换集时取消。
5. 恢复先确认内容身份，再应用几何偏移：比例只作为最后回退，不作为唯一定位依据。
6. 旧记录兼容：已有 `chapter_url`、`position`、`page` 数据继续可恢复，新增字段缺失时走旧逻辑。

## 视频播放设计

### 1. 统一播放诊断

在现有代理转发路径内统一记录低开销指标，不主动制造请求：

- 协议类型：HLS、DASH、MP4/Range 或未知。
- 请求类别：manifest、segment、key、media、range。
- 首字节耗时、有效吞吐、响应长度、缓存命中/未命中、等待锁耗时。
- 上游路由、状态码、失败类别和重试结果。
- 单播放会话的缓冲/断流次数（若播放器回调可用）。

诊断记录必须有界、线程安全，并且不保存完整 URL、Cookie、Authorization、token 或响应正文。指标计算异常不得影响媒体转发。

### 2. 公共代理与缓存优化

优先审查并优化所有源共享的路径：

- 保持 HTTP 响应定界正确，能复用连接时不因固定 `Connection: close` 触发重复握手。
- HLS 清单和分片首字节采用流式转发，不进行大块无必要预读。
- 相同媒体 URL 的并发请求使用单飞/请求去重，避免多个播放器请求同时回源。
- 完整响应从头开始时才写入临时缓存；Range 请求必须保持正确的 206、Content-Range 和长度语义，不能污染完整缓存。
- 缓存写入采用临时文件、完成提交和失败清理；播放器命中已完成文件时直接本地响应。
- 缓存锁只保护同一媒体资源，锁外执行不会阻塞转发的工作；任何预取钩子不得在持锁路径内重新获取同一把锁。
- 对长连接、提前断流、上游长度错误和客户端断开分别处理，避免连接复用造成下一请求错位。

### 3. 通用异步策略

不根据源 ID 写专门逻辑。运行时仅允许以下公共行为：

- manifest 已经声明后续分片时，按统一的有限窗口决定是否预取。
- 默认不主动预取；若后续证据证明公共缓存存在等待，可启用统一的小窗口策略。
- 并发数、前瞻深度、单任务超时和总任务数均有硬上限。
- 同一 URL 去重；播放器请求优先于后台任务。
- 出现 403、429、连续连接失败或上游明显降速时自动熔断本次后台任务，不扩大请求压力。
- 播放器离开、切源、切集或代理停止时取消未完成任务。

### 4. 播放参数

保留现有按媒体协议分类的默认参数，但不再把某个源的固定配置作为通用优化依据。公共播放层根据可用指标选择保守缓冲值：

- 正常源不因全局固定高缓冲增加不必要的起播等待。
- HLS/DASH 使用分片流适用的缓存下限；MP4/Range 使用渐进下载适用的策略。
- 运行时调整必须只影响当前播放会话，不污染其他源或后续会话。
- `MediaTuner` 若继续保留，必须接入真实缓冲事件；未接入前不得宣称具备自适应能力。

## 精准阅读位置设计

### 1. 通用进度记录

`ReadingProgress` 继续按作品 key 保存章节级记录，并扩展可选的 `location` 对象。建议结构：

```json
{
  "chapter_url": "...",
  "chapter_title": "...",
  "content_type": "novel",
  "position": 0.42,
  "page": 5,
  "location": {
    "kind": "novel-anchor",
    "anchor_text": "该段落开头的稳定文本片段",
    "anchor_hash": "sha256:...",
    "offset": 18,
    "chapter_content_hash": "sha256:...",
    "scroll_ratio": 0.42,
    "layout": {"viewport_w": 800, "viewport_h": 600, "font_px": 17}
  }
}
```

漫画位置使用：

```json
{
  "location": {
    "kind": "comic-anchor",
    "image_index": 12,
    "image_key": "稳定图片 URL 或其 hash",
    "image_offset_ratio": 0.37,
    "scroll_ratio": 0.37,
    "layout": {"viewport_w": 800, "viewport_h": 600, "zoom": 1.0}
  }
}
```

字段全部可选，旧记录只使用现有 `position`/`page`。

### 2. 小说定位

保存位置时，从当前章节正文生成稳定的规范化文本：统一空白、去除仅用于显示的章节头，并按段落或固定字符窗口建立锚点。锚点至少包含：

- 当前可见位置附近的文本片段。
- 片段在正文中的字符偏移。
- 章节正文指纹。
- 锚点内相对偏移和当前滚动比例。

恢复时：

1. 先确认章节 URL；章节 URL 不匹配时不消费旧锚点。
2. 正文内容指纹相同，按保存的字符偏移定位。
3. 指纹变化时，在当前正文中搜索锚点文本或其规范化片段，选择唯一/最佳匹配。
4. 将锚点对应的 QLabel/QText 文本位置转换为滚动值，并在布局完成后重试有限次数。
5. 锚点找不到时回退到 `page`，再回退到 `position`。

字号、窗口变化只重新计算布局和滚动映射，不改变内容锚点；恢复完成后重新保存新的布局信息。

翻页模式仍保存页索引，但页索引只是同一内容布局下的快速路径，不能覆盖锚点。

### 3. 漫画定位

保存位置时记录当前章节、图片序号和图片身份。图片身份优先使用已解析的稳定 URL，必要时保存图片内容 hash；同时保存图片内相对位置。

恢复时：

1. 先确认章节 URL。
2. 根据图片索引定位候选图片。
3. 若索引变化，根据图片 URL/hash 在当前图片列表中寻找同一图片。
4. 等目标图片和前置布局完成后，将视口滚动到该图片顶部加保存的图片内比例。
5. 图片不可用时回退到章节滚动比例。

懒加载、缩放、窗口大小变化只触发布局重算和有限重试，不使用旧滚动像素直接恢复。换书、换话和旧异步任务必须通过现有代际/epoch 守卫，不能消费其他作品的恢复状态。

### 4. 写入节流与退出保障

- 滚动事件继续节流，避免每个像素写磁盘。
- 章节切换、窗口关闭、切换阅读 Tab 和应用退出强制 flush 一次。
- 进度写入使用临时文件替换或等价的原子写策略，避免进程中断产生半个 JSON。
- 保存失败不影响阅读；下次启动保留最后一份有效记录。

## 测试设计

### 视频

- HLS manifest/segment/key、DASH、MP4 和 Range 的公共转发回归。
- 同一资源并发请求只产生一次上游请求，缓存完成后后续请求不回源。
- 首字节和吞吐只来自实际读取，不因诊断额外请求。
- 提前断流、错误响应、长度错位、客户端断开不会污染下一请求。
- 预取默认关闭；开启时验证深度、并发、去重、超时、熔断和取消。
- 代理停止、切源和切集后无后台任务继续写错误缓存。

### 小说

- 保存并恢复同一段落的锚点。
- 正文内容变动时通过锚点文本重新定位。
- 字号和窗口变化后仍定位到同一段落附近。
- 翻页模式同时验证页索引和锚点回退链。
- 换书时旧书恢复任务不会修改新书位置。
- 旧版只有 `position`/`page` 的记录可正常恢复。

### 漫画

- 恢复到同一话、同一张图片和图片内位置。
- 图片懒加载和布局延迟时有限重试最终定位正确。
- 图片列表发生插入/删除时按 URL/hash 找到原图片。
- 缩放和窗口变化后仍定位同一图片。
- 换书/换话时旧恢复任务不会滚动新内容。

## 验收标准

1. 所有视频协议的公共播放链路有可验证的性能基线和回归测试。
2. 优化不要求修改每个视频源配置，不主动批量读取源，不默认增加上游请求压力。
3. 相同媒体资源的并发请求不会重复回源，缓存命中不破坏 Range/流式语义。
4. 小说重启、换字号、改窗口后恢复到同一章节同一段落附近；锚点失效时按明确回退链工作。
5. 漫画重启、懒加载、缩放和改窗口后恢复到同一话同一张图片及相对位置附近。
6. 小说和漫画位置不串书、不串章节、不被旧异步任务覆盖。
7. 旧阅读进度文件保持兼容，视频位置不纳入本功能。
8. 相关专项测试、lint、typecheck/compile 检查通过；Qt 进程级崩溃等既有环境限制单独记录。
