# 书架卡片懒加载详情设计

日期：2026-10-06
状态：用户已批准方案 A

## 目标

应用启动时不加载书架卡片内容；用户点击「书架」Tab 后，只读取卡片显示所需的轻量元数据。用户点击具体卡片后，才加载该卡片对应的本地缓存或在线详情/目录，不加载其它卡片。

## 行为边界

- 本地 EPUB、漫画和视频卡片保持点击即打开本地内容，不触发网络详情请求。
- 应用启动阶段不构造书架页面，不扫描书架文件，不读取书架卡片列表。
- 点击「书架」Tab 后才执行本地文件扫描、收藏记录读取、卡片排序/筛选、阅读进度读取和封面异步加载。
- 点击具体卡片前禁止 `fetch_detail()`、章节目录请求、正文预缓存和其它卡片缓存读取。
- 在线卡片点击后显示加载状态，后台调用现有详情接口；成功后进入 ReaderPage，失败显示可重试错误，不阻塞主线程。
- 快速点击不同在线卡片时，旧详情响应不得覆盖当前点击目标。
- 相同在线卡片重复点击时复用正在进行的请求，避免重复网络请求。

## 现状根因

`MainWindow._build_pages()` 当前启动时同步构造书架、发现和搜索页面；书架构造/扫描及发现页网络任务会与启动自检叠加。书架卡片本身使用轻量收藏记录，但点击路径需要独立的详情加载状态和请求代次保护。

## 设计

### 0. 启动与书架 Tab 边界

启动只构造首页、阅读器占位和必要的应用基础设施；发现、搜索、书架、源管理、设置等页面延迟到用户第一次点击对应 Tab 时构造。启动不启动发现预加载或全源自检；源健康诊断改为用户进入源管理后手动/按需执行。

书架 Tab 第一次打开时，才构造 `LibraryPage` 并扫描本地文件、读取书架记录和封面。书架刷新只更新卡片元数据，不调用详情、章节或正文缓存。

### 1. 轻量书架记录

`ShelfService.list_items()` 和 `ShelfItem.to_rec()` 继续返回卡片所需字段，不主动构造完整 `Detail`。在线收藏记录只携带 `source_id`、作品 URL、类型、标题、作者、封面、标签、收藏夹和阅读进度等元数据。若历史缓存中带有 `detail`，书架渲染和启动流程忽略其章节字段，不启动预缓存。

### 2. 点击在线卡片懒加载

`LibraryPage._open_rec()` 对在线记录改为启动 `_DetailLoadTask`：

- 以 `(source_id, url)` 作为请求键；
- 当前请求存在时不重复启动；
- 使用递增 generation 标记当前点击；
- 后台调用 `content.fetch_detail(source, url)`；
- 回主线程后只有 generation 和请求键都匹配才发出 `open_online_requested`；
- 失败通过卡片状态或消息框显示，并清除请求状态，允许再次点击重试。

本地路径分支不变，直接发出 `open_epub_requested` 或 `play_local_video_requested`。

### 3. 封面与详情分离

卡片封面继续使用 `CoverLoader` 异步加载；封面补全只允许使用轻量 `fetch_cover()`，不得升级为 `fetch_detail()`。若补全逻辑无法确认轻量接口可用，则跳过补全而不是请求完整详情。

### 4. 预缓存边界

`LibraryPage._precache_book()` 只允许在用户明确执行“缓存本书”操作后运行。启动、卡片构造、卡片封面加载和在线详情加载都不自动触发正文预缓存。

## 测试

- 构造主窗口时，断言书架、发现和搜索页面不构造、不启动网络任务。
- 第一次点击书架 Tab 时，只读取卡片元数据和封面，不调用 `fetch_detail()`、章节列表请求或正文预缓存。
- 点击在线卡片，断言详情请求在后台发生，成功后只发出一次打开信号。
- 点击本地 EPUB/漫画/视频，断言直接发出本地打开信号且不调用在线接口。
- 点击 A 后快速点击 B，A 的迟到回调不得打开 A；B 成功后打开 B。
- 点击同一在线卡片两次，断言复用在途任务，不重复调用详情。
- 启动、书架、阅读器 GUI smoke 和相关回归通过。
