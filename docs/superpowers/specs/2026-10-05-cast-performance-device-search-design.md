# 投屏流畅性诊断与手动设备搜索设计

日期：2026-10-05
状态：用户已批准

## 目标

修复两类问题：

1. 投屏端比应用端更卡时，能够区分上游 CDN、MediaProxy、电视端缓冲和编码/转码问题，并对确认需要的源启用按源调优。
2. 打开投屏设备窗口时不自动发起 SSDP 搜索；立即显示历史设备，只有用户点击「搜索设备」或「刷新」才扫描。

## 投屏性能方案

不改变应用端 VLC 播放路径。投屏链路增加可观测指标：

- HLS 清单请求时间；
- 分片首字节时间、下载字节数和耗时；
- 代理命中/上游转发分类；
- MediaProxy 当前活动请求数；
- 原始流/转码流的首播状态和首片段时间。

指标只记录脱敏 URL 特征、媒体类型、源 id 和数值，不记录 token、Cookie 或完整媒体 URL。

B 站使用源级配置：

- 保持当前 `durl` 单流播放，不擅自切换画质或转码；
- 仅在投屏 HLS/代理路径确认需要时启用有限预取；
- 调整电视投屏端的 HLS 缓冲，不影响应用端播放器；
- 不对所有源全局开启并发预取，避免触发风控和增加带宽竞争。

## 设备搜索方案

`CastDeviceDialog` 构造时加载历史设备并填充列表，`showEvent` 只更新窗口，不启动扫描。状态行增加「搜索设备」按钮：

- 点击后清理当前扫描结果中的非历史设备，启动后台 SSDP 扫描；
- 「刷新」保留为同义重新搜索入口；
- 历史设备始终保留并置顶；扫描结果更新历史设备 IP/控制地址；
- 无历史且未搜索时显示「点击搜索设备」提示；
- 扫描线程、错误、取消和清理行为保持现有实现。

## 验收

- 打开投屏窗口不调用 `discover_renderers`；
- 点击「搜索设备」调用一次扫描并显示设备；
- 历史设备立即可选；
- B 站及其他源诊断能输出分片速度/延迟分类；
- 相关性能测试和全量投屏回归通过。
